# Phase 3 — UI Design Contract

> Visual and interaction contract for the Home page (SHELL-01, SHELL-02, SHELL-03, REFR-01). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Stack is fixed: Windows PowerShell 5.1 + inbox WPF/XAML. There is no component library. Every value below comes from the existing `UI/MainWindow.xaml` resources and the `Tuner` panel and tweak-row look, so Home matches the pages users already know. Only the Home page uses the new values. Existing chrome (sidebar, search bar, log drawer, tweak rows) stays as it is.

## Layout Contract

### Sidebar (D-13, D-14)

- `Home` is the first `Nav` RadioButton (`Content='Home'`, `Tag='Home'`, `GroupName='nav'`, `Style=Nav`), and comes before `Check`.
- Directly after Home, add a divider: `Border Height=1 Background=Bd Margin=8,8,8,8`. Then Check … Advanced follow, unchanged.
- The divider is not a nav item. It must not be clickable or focusable (`IsHitTestVisible=False`, `Focusable=False`).
- On launch, Home is checked (`$script:Cat = 'Home'`). The selected-bar accent shows on Home.

### Home page structure (inside the existing `Page` StackPanel, above `Rows`)

```
Page (existing StackPanel, Margin 16,14 — unchanged)
├─ Heading (existing)            → Collapsed while Home is showing
├─ Home  (new StackPanel)        → Visible only when Cat = Home AND search box is empty
│   ├─ HomeHeader (DockPanel, Margin 0,0,0,16)
│   │   ├─ [right side left empty — reserved for Phase 4 copy button]
│   │   └─ StackPanel
│   │       ├─ HostName  TextBlock  22 / SemiBold / Tx
│   │       └─ HostSub   TextBlock  13 / Regular / Mu, Margin 0,4,0,0
│   └─ Cards (WrapPanel, Orientation Horizontal)
│       └─ 6 × Card Border (order: CPU, GPU, RAM, Disk, Board, Windows)
├─ Tuner / SvcTuner (existing)   → Collapsed on Home
└─ Rows (existing)               → Empty on Home; must NOT show "Nothing here yet."
```

Suggested names for `FindName` and shortcuts: `Home`, `HostName`, `HostSub`, `Cards`. Add them to the existing `Set-Variable` shortcut list.

### Card (D-02 … D-05)

| Property | Value | Source |
|----------|-------|--------|
| Element | `Border` | matches `Tuner` |
| Width | **240** (fixed) | Gives 2 columns at MinWidth 820 and 3 columns at the default 1000 width, scrollbar included |
| Background / Border | `S1` / `Bd`, `BorderThickness=1` | D-05 |
| CornerRadius | 5 | matches `Tuner`/`SvcTuner` and tweak rows |
| Padding | `16,12` | |
| Margin | `0,0,8,8` (8px gap right and below) | |
| Vertical alignment | Leave the default (Stretch). WrapPanel then gives every card in a row the height of the tallest card in that row. | |

Card content, from top to bottom:

1. **Title.** Card name, 12 / SemiBold / `Mu`, `Margin 0,0,0,4`.
2. **Headline line.** The card's main value, 15 / SemiBold / `Tx`, `TextWrapping=Wrap`, `Margin 0,0,0,8`.
3. **Field rows.** `Grid` with columns `72` | `*`, each row `Margin 0,4,0,0` (the first row uses `0`).
   - Label: 12 / Regular / `Mu`, `VerticalAlignment=Top`, no wrapping.
   - Value: 13 / Regular / `Tx`, `TextWrapping=Wrap`, left-aligned in the value column (matches the CONTEXT mock).
4. **Multi-item cards (GPU, Disk; D-04).** Each adapter or volume is its own block (headline line plus field rows). Between blocks, add a `Border Height=1 Background=Bd Margin=0,12,0,12`. Do not add a divider before the first block or after the last one.

### Per-card content map (all Phase 1–2 fields are shown)

| Card | Title | Headline line | Rows (Label → Value) |
|------|-------|---------------|----------------------|
| CPU | `CPU` | `CPU.Model` | `Cores` → `{Cores} / {Threads} threads` · `Speed` → `{SpeedMHz/1000:0.00} GHz` |
| GPU | `GPU` | per adapter: `Model` | `VRAM` → `{VRAM_GB:0.0} GB` · `Driver` → `{DriverVersion}` · `Status` → `{Status}` (**only when Status ≠ 'OK'**) |
| RAM | `RAM` | `{TotalGB:0.0} GB` | `Used` → `{UsedGB:0.0} GB` · `Free` → `{FreeGB:0.0} GB` |
| Disk | `Disk` | per volume: `{Drive}` plus two spaces and `{Label}` when Label is not empty (e.g. `C:  Windows`) | `Free` → `{FreeGB:0.0} GB` · `Total` → `{TotalGB:0.0} GB` · `File system` → `{FileSystem}` |
| Board | `Board` | `{Manufacturer} {Product}`. If only one is available, show just that one. If neither, show `Not available`. | `BIOS` → `{BIOSVersion}` · `Released` → `{ReleaseDate}` (already `yyyy-MM-dd`) |
| Windows | `Windows` | `Edition`, with a leading `Microsoft ` removed for display only (e.g. `Windows 11 Pro`) | `Version` → `{Version}` · `Build` → `{Build}` |

Formatting rules (prescriptive):

- Numbers are formatted with `[Globalization.CultureInfo]::InvariantCulture`, so the decimal separator is always `.`. GB values use `0.0` (`31.9 GB`, `0.0 GB`, `8.0 GB`). GHz uses `0.00` (`4.20 GHz`).
- If a field value is the string `Not available`, show it exactly as `Not available` in `Mu` (13 / Regular), with no unit. Never show `Not available GB`.
- CPU `Cores` row with partial data: if both values are present, show `8 / 16 threads`. If only cores, `8`. If only threads, `16 threads`. If neither, `Not available`.
- Unit separator is a single space (`4.20 GHz`, `12.0 GB`).

### Header (D-11, D-12)

- `HostName` = `$env:COMPUTERNAME`, shown as Windows reports it (uppercase). It is available immediately at launch and never shows "Loading…". `TextTrimming=CharacterEllipsis`, single line.
- `HostSub` = `{Maker} · {Model}` (the separator is space + U+00B7 middle dot + space).
  - Source order: `Win32_ComputerSystem` Manufacturer/Model. If either is SMBIOS filler (`Test-SmbiosValue` fails), use Motherboard Manufacturer/Product instead. If both pairs are filler, set `HostSub` to Collapsed so only the computer name shows.
  - If exactly one of the pair is valid, show just that one, with no dot.
  - Single line, `TextTrimming=CharacterEllipsis`. Set `ToolTip` to the full text.
  - Before the first spec read finishes, `HostSub` is Collapsed. Do not show "Loading…" in the header.

## Typography

Home uses exactly 4 sizes and 2 weights. Do not set `LineHeight`. Use the WPF default for Segoe UI, which is about 1.33.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 12px | SemiBold (600) for card titles; Regular (400) for field labels | ~1.33 (WPF default) | Card title (`Mu`), field labels (`Mu`) |
| Body | 13px | Regular (400) | ~1.33 (WPF default) | Field values (`Tx`), `HostSub` (`Mu`), "Loading…", "Not available" |
| Heading | 15px | SemiBold (600) | ~1.33 (WPF default) | Card headline line (CPU model, GPU model, RAM total, drive, board, edition). Same size and weight as the existing page `Heading`. |
| Display | 22px | SemiBold (600) | ~1.2 (WPF default at this size) | Computer name in the Home header |

Weights: Regular (400) and SemiBold (600) only. Do not use `Medium` on Home. It is used in the existing Tuner and rows, but Home stays at two weights.

## Interaction & State Contract

### When specs refresh (D-16)

A spec read starts whenever Home appears:

1. App launch (Home is the default).
2. The user clicks Home in the sidebar, including clicking it again while already on Home. A `Checked` event only fires on change, so re-clicking the selected Home does nothing. That is acceptable.
3. The search box is cleared while Home is selected, and Home reappears.

It must **not** start when the page redraws automatically after a tweak finishes. The only exception is the D-09 deferred read below. There must be no refresh loop.

### Visual states per card

| State | When | What the user sees |
|-------|------|--------------------|
| First load | No spec data yet (first Home show this session) | Card title, then `Loading…` (13 / Regular / `Mu`) in place of the headline and rows. No spinner, no progress bar. |
| Refreshing | Earlier data exists and a new read is in progress, or waiting for a running tweak (D-09) | Previous values stay in place with `Opacity=0.6` on the `Cards` WrapPanel and on `HostSub`. `HostName` stays at full opacity. Nothing is cleared, so nothing flickers. |
| Fresh | Read completed | All cards rebuilt or updated in a single pass, `Opacity` back to `1`. There is no fade animation; values swap instantly. |
| Partial group (`_Status = 'Partial'`) | Some fields failed | The failed fields show `Not available` in `Mu`. The other fields show normally. |
| Failed group (`_Status = 'Failed'`) | Whole group failed | The card is still rendered. Headline line shows `Not available` (15 / SemiBold, `Mu`). Rows are still listed with `Not available` values. For GPU/Disk with zero items, show only the headline `Not available` and no rows. |
| Read crashed | The background read threw or returned nothing | If earlier data exists, keep it and restore `Opacity=1`. If it was the first load, every card switches from `Loading…` to its Failed-group look. A card must never stay on `Loading…` after a read ends. One line is written to the log drawer (see Copywriting). |

### Concurrency (D-08 … D-10)

- While specs load, the sidebar, search box, other pages and all tweak buttons stay fully enabled. The spec read must not call `Set-Busy` and must not set `$script:Busy`.
- Starting a tweak while specs load is always allowed.
- If Home is shown while a tweak is running, show the last values (dimmed) or `Loading…`. Read specs automatically once the tweak finishes, only once.
- If the user leaves Home mid-read, the result is still stored. The next time Home shows, those values appear immediately (dimmed) while a new read starts.

### Search (D-15)

- Typing on Home hides the `Home` panel, shows `Heading` = `Results for "{query}"` and the matching tweak rows, exactly as today.
- Clearing the search hides `Heading`, shows the `Home` panel again with the last values, and starts a refresh.
- On Home with an empty search, `Rows` stays empty and the `Nothing here yet.` message must not appear.

### Keyboard and accessibility

- Home nav item is reachable by Tab and arrow keys like the other `Nav` items. Cards are not focusable (`Focusable=False`); they are read-only.
- Contrast on `S1`: `Tx` is about 17:1 and `Mu` is about 5.6:1, both above WCAG AA. While dimmed at 0.6, values stay readable (`Tx` is about 6.5:1). The dimmed state is temporary by design.
- Text is not selectable in Phase 3. Copying comes in Phase 4.

## UI Considerations

Applicable state considerations resolved: 9 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Spec cards (first visit) | ✅ covered | On first Home show of a session, each card shows its title and `Loading…` in Mu until the first read completes |
| loading | Spec cards (later visits) | ✅ covered | On later Home shows, the previous values stay visible at 0.6 opacity until fresh values replace them in one pass, and nothing is cleared |
| loading | Home header | ✅ covered | The computer name shows immediately at launch, and the Maker · Model line stays hidden until the first read completes |
| error | Spec cards | ✅ covered | A failed read never leaves a card on `Loading…`. Earlier values are kept, or Failed-group cards are shown, and one `Specs: Read failed (…)` line is logged (see Copywriting) |
| partial | Spec cards | ✅ covered | Fields that failed show `Not available` in Mu, while the other fields in the same card show normally |
| empty | GPU / Disk cards with zero items | ✅ covered | A GPU or Disk group with no adapters or volumes renders a card whose headline reads `Not available` with no rows |
| zero-one-many | GPU adapters, disk volumes | ✅ covered | One item renders as a single block with no divider. Many items stack inside one card, separated by a 1px Bd divider with 12px above and below. |
| overflow | Card grid | ✅ covered | Cards wrap into as many 240px columns as fit (2 at minimum window width, 3 at default). Extra height scrolls vertically in the existing page scroller, and there is never a horizontal scrollbar. |
| populated | Card grid | ✅ covered | Six cards appear in the order CPU, GPU, RAM, Disk, Board, Windows, and cards in the same row share the tallest card's height |
| long-text | GPU/CPU/board model names, field values | 🧪 backstop | Long model names and values wrap inside the 240px card and never clip or push the card wider; labels stay on one line in the 72px column |
| long-text | Maker · Model header line | 🧪 backstop | A long maker/model line is cut off with an ellipsis on one line, and hovering shows the full text in a tooltip |
