# Phase 3 Plan 1: Home Shell, Live Read, Card Renderer

## Phase Goal

**As a** user, **I want to** land on Home by default and see my system specs in a card grid, **so that** I can see accurate, live system specs at a glance.

> Restated from ROADMAP.md `**Goal:** Home as default landing with card grid, live refresh, and navigation` plus PROJECT.md's core value. The roadmap goal line is not itself in user-story form; no new capability is introduced by this wording. To ratify the wording in ROADMAP.md, run `/gsd-mvp-phase 3`.

## Objective

Build the working end-to-end path: Home becomes the default landing tab, a background channel reads specs off the UI thread every time Home appears, and a card renderer turns the read into the live CPU card. Plan 03-02 then completes the remaining five cards' states and the host header line.

Purpose: prove the architecture — XAML panel, sidebar item, page-branch trigger, second background channel, timer harvest, UI-thread renderer — on one real path before filling in content.

Output: `Akari.ps1` gains the Home state, the `$HostIdentityFunc`/`$SpecReadCode` composite read, `Start-SpecRead`, the spec-completion block inside the existing 150 ms tick, the sidebar Home item with divider, and `Update-Home` plus its card helpers. `UI/MainWindow.xaml` gains the static Home panel. Task 1 lands the thinnest slice (CPU card); Task 2 completes the six-card content map.
